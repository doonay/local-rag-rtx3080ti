# Локальная RAG-система для RTX 3080 Ti

Локальная Windows-программа для загрузки PDF, TXT и MD, поиска по документам и генерации ответов со ссылками на найденные фрагменты.

## Что понадобится

- Windows 10 или Windows 11, 64-bit;
- NVIDIA RTX 3080 Ti с 12 ГБ VRAM;
- актуальный драйвер NVIDIA;
- Python 3.11, 64-bit;
- минимум 24 ГБ RAM, рекомендуется 32 ГБ;
- минимум 15 ГБ свободного места, рекомендуется 20 ГБ;
- интернет для первой установки и загрузки моделей.

Дополнительные серверы и WSL не требуются. Все модели, индекс документов и логи хранятся внутри папки проекта.

## 1. Установка Python

Проект проверен на Python 3.11.
1. Скачайте Python 3.11 с [официального сайта](https://www.python.org/downloads/windows/).
2. Запустите установщик.
3. На первом экране обязательно отметьте **Add python.exe to PATH**.
4. Завершите установку.

## 2. Скачивание проекта с GitHub (Самый простой способ):

1. Откройте страницу репозитория и убедитесь, что выбрана ветка **main**.
2. Нажмите зелёную кнопку **Code**.
3. Выберите **Download ZIP**.
4. Распакуйте архив. Желательно использовать короткий путь латиницей, например `C:\LocalRAG`.

Если Git уже установлен, вместо ZIP можно выполнить:
```powershell
git clone https://github.com/doonay/local-rag-rtx3080ti.git
```

## 3. Первый запуск

1. Откройте распакованную папку проекта.
2. Запустите `start-local.bat`.
3. Не закрывайте появившееся окно во время установки.

При первом запуске программа автоматически:

- создаст отдельное Python-окружение `.venv-local`;
- установит PyTorch и остальные зависимости;
- скачает Windows-сборку llama.cpp;
- скачает `Qwen3-8B-Q4_K_M.gguf`, BGE-M3 и Qwen3-Reranker-0.6B;
- запустит модели и откроет браузер.

Первая установка загружает несколько гигабайт и может занять 20–60 минут. Скорость зависит от интернета, диска и процессора. Если загрузка прервалась, снова запустите `start-local.bat`: скачивание продолжится с сохранённого места.

После установки модели могут загружаться в память ещё несколько минут. Успешный запуск выглядит так:

```text
Local RAG is ready: http://127.0.0.1:8000
```

Браузер должен автоматически открыть <http://127.0.0.1:8000>. Если он не открылся, перейдите по этому адресу вручную.

## 4. Полная проверка через интерфейс

Эта проверка последовательно проверяет чтение документа, BGE-M3, Qdrant Local, reranker и генерацию ответа.

1. Создайте файл `proverka.txt` со следующим содержимым:

```text
Компания «Север» основана в 2019 году.
Её директор — Анна Смирнова.
Главный офис находится в Казани.
```

2. В Web UI нажмите область **Загрузка документов** и выберите `proverka.txt`.
3. Дождитесь сообщения `Загружено: 1 файлов`.
4. Убедитесь, что файл появился в списке **Загруженные документы**.
5. Задайте вопрос: `В каком году основана компания Север?`
6. Правильный ответ должен содержать `2019` и ссылку на фрагмент из `proverka.txt`.
7. Задайте второй вопрос: `Где находится главный офис?`
8. Правильный ответ должен содержать `Казань`.
9. Обновите страницу браузера. Документ должен остаться в списке.
10. Нажмите удаление документа и подтвердите действие. Файл должен исчезнуть из списка.

Если все десять шагов выполнены, основной RAG-пайплайн работает полностью.

## 5. Техническая проверка

Откройте папку проекта в Проводнике, щёлкните адресную строку, введите `powershell` и нажмите Enter.

Проверьте локальное API:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health | Format-List
```

В результате должны присутствовать:

```text
status            : healthy
reranker_device   : cuda
llm_backend       : llama.cpp
```

Проверьте llama.cpp:

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health
```

Проверьте использование видеокарты:

```powershell
nvidia-smi
```

В списке процессов должны быть `llama-server.exe` и Python-процесс reranker.

## 6. Запуск автоматических тестов

Эта проверка необязательна для обычного использования, но полезна после скачивания новой версии проекта:

```powershell
.\.venv-local\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv-local\Scripts\python.exe -m pytest -q
```

Ожидаемый итог:

```text
17 passed
```

## 7. Остановка и повторный запуск

Для правильной остановки дважды щёлкните `stop-local.bat`.

Для повторного запуска снова используйте `start-local.bat`. Модели и зависимости повторно не скачиваются, но их загрузка в RAM и VRAM всё равно может занять несколько минут.

Не закрывайте процессы через диспетчер задач, если `stop-local.bat` доступен.

## Если программа не запустилась

### Не найден Python

Если появляется ошибка про Python:

1. установите Python 3.11 заново;
2. отметьте **Add python.exe to PATH**;
3. закройте и заново откройте PowerShell;
4. проверьте `python --version`;
5. снова запустите `start-local.bat`.

### Прервалось скачивание

Повторно запустите `start-local.bat`. Скрипт использует докачку и не должен загружать уже полученные файлы заново.

### Недостаточно памяти видеокарты

Закройте игры, программы генерации изображений, другие LLM и приложения, использующие CUDA. Затем запустите `stop-local.bat` и повторите запуск. Проверить занятую VRAM можно командой `nvidia-smi`.

### Окно сообщает об ошибке запуска

Откройте PowerShell в папке проекта и посмотрите последние строки логов:

```powershell
Get-Content .local\logs\llama.stderr.log -Tail 100
Get-Content .local\logs\api.stderr.log -Tail 100
```

Для чистого повторного запуска сначала выполните `stop-local.bat`, затем `start-local.bat`.

## Где хранятся данные

- `.local/models` — основная GGUF-модель;
- `.local/cache` — кэш BGE-M3 и reranker;
- `.local/qdrant` — индекс загруженных документов;
- `.local/logs` — журналы запуска и ошибок;
- `.venv-local` — изолированное Python-окружение.

Эти папки не публикуются в GitHub. Не удаляйте `.local/qdrant`, если хотите сохранить загруженные документы и индекс.
