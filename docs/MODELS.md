# Выбор моделей для RTX 3080 Ti 12 ГБ

## Итоговый профиль

| Этап | Модель | Где работает | Причина выбора |
|---|---|---|---|
| Dense+sparse embeddings | [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3) | CPU | Мультиязычная модель, одновременно возвращает dense и learned sparse vectors; подходит для настоящего hybrid retrieval |
| Повторное ранжирование | [Qwen/Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) | GPU FP16 | Новая instruction-aware модель на 0.6B параметров, поддерживает 100+ языков и длинный контекст |
| Генерация, локальный Windows-режим | [Qwen/Qwen3-8B-GGUF](https://huggingface.co/Qwen/Qwen3-8B-GGUF), Q4_K_M | GPU через llama.cpp | Нативный переносимый Windows backend без WSL/Docker |
| Генерация, Docker-режим | [Qwen/Qwen3-8B-AWQ](https://huggingface.co/Qwen/Qwen3-8B-AWQ) | GPU AWQ 4-bit через vLLM | Серверный backend для контейнерного развёртывания |

## Зачем нужен reranker

Embedding-поиск оптимизирован на быстрый recall: его задача — не пропустить потенциально полезный фрагмент. Поэтому top-20 содержит как хорошие, так и похожие лишь по словам чанки.

Reranker получает одновременно вопрос и полный текст каждого кандидата, вычисляет более точную релевантность и оставляет top-5. Это:

- уменьшает нерелевантный контекст;
- снижает галлюцинации LLM;
- улучшает ответы на вопросы с отрицаниями, условиями и близкими терминами;
- экономит KV-cache и время генерации.

## Бюджет памяти

- vLLM получает до 70% VRAM, около 8.6 ГБ;
- Qwen3 Reranker 0.6B FP16 и CUDA overhead используют оставшийся запас;
- BGE-M3 намеренно оставлен на CPU;
- контекст LLM ограничен 8192 токенами, одновременных последовательностей — две.

14B AWQ можно попытаться запустить только ценой короткого контекста и переноса reranker на CPU. Для постоянно работающей системы на 12 ГБ это менее устойчивый профиль.
