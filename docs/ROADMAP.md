# Дорожная карта

## P0 — первый стабильный релиз

1. Запустить полный Compose на RTX 3080 Ti и записать фактические VRAM/RAM, время старта и latency для 10–20 запросов.
2. Выполнить и стабилизировать подготовленные integration/E2E-тесты на реальном стеке: загрузка TXT → вопрос → ответ с источником.
3. Добавить CI: compile, unit-тесты, линтер, проверка Compose и сборка CPU-образов. GPU/E2E оставить отдельным ручным job.
4. Инициализировать Git, зафиксировать чистую базу и только после этого удалить `archive/legacy`.

Критерий готовности: стек поднимается одной командой после чистой установки, health-checks зелёные, повторный запуск не теряет индекс.

## P1 — корректность RAG

1. Хранить точный номер страницы и символьные границы каждого чанка, чтобы цитаты были проверяемыми.
2. Ограничивать общий токен-бюджет контекста, а не только количество чанков.
3. Добавить streaming ответа через SSE.
4. Добавить изменение параметров поиска и фильтр документа в Web UI.

Критерий готовности: один и тот же документ не индексируется дважды, источники ведут к правильной странице, retrieval измеримо лучше dense-only baseline.

## P2 — качество документов и эксплуатация

1. Добавить DOCX/HTML, затем OCR для сканированных PDF. OCR вынести в отдельный профиль, потому что он тяжёлый.
2. Сделать фоновую ingestion-очередь и показывать пользователю прогресс обработки.
3. Добавить структурированные логи, Prometheus-метрики, correlation/request ID и простой dashboard.
4. Ввести резервное копирование Qdrant snapshots и лимиты хранения.
5. Закрыть API аутентификацией, rate limit и проверкой MIME/содержимого файлов перед внешним доступом.

## P3 — измеримое качество

1. Собрать 50–100 эталонных вопросов по реальным документам с ожидаемыми источниками.
2. Измерять recall@k, MRR/nDCG retrieval, долю корректных цитат, groundedness и p95 latency.
3. Сравнить размеры чанков 600/1000/1500 символов, overlap 10–20%, top-k и разные reranker.
4. Сравнить Qwen 7B AWQ с компактной 3B-моделью на тех же данных; модель менять только по результатам eval, а не субъективно.

## Известные ограничения текущей базы

- интеграционные и E2E-тесты приведены к новым контрактам, но ещё не проверены на полном GPU-стеке;
- dense+sparse retrieval реализован, но его качество ещё не измерено на пользовательском eval-наборе;
- PDF без текстового слоя не распознаются;
- нет удаления документов, авторизации, streaming и наблюдаемости;
- полноценная Docker/GPU-проверка не выполнена, пока Docker Desktop выключен.
